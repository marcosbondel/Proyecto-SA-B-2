# Design

Use this document for durable product and interaction design guidance.

## Principles

- Start with real user workflows, not screens.
- Prefer interfaces that are easy to scan and hard to misuse.
- Make state visible: loading, empty, error, success, and permission states.
- Keep language precise, calm, and action-oriented.
- Document design decisions that affect repeated implementation choices.

## Decision Records

Design decisions should live in `docs/design-docs/` and be linked from
`docs/design-docs/index.md`.

## Open Questions

- Who is the primary user?
- What job are they trying to complete?
- What does a successful first session look like?
- What constraints should every UI respect?
